# 讨论结果落档速查（Obsidian 快速填写对应）

> **用途**：把设计区讨论产物（裁定表八批、审计 Q/E 系列、地图巡检、留钩子 H01-50、会议共识）快速对应填进本 vault（MEDNarrative）结构。
> **原则**：设计区文档（MED-TextScript 根下：裁定表/大纲/审计/钩子）＝**真值源**；本 vault＝**可执行落点**（卡/流程/导出）。先落真值源，再按本表同步 vault。
> **禁区**：运行时数据（声望当前值/发现状态/状态等级/任务进度）禁止写入 frontmatter——卡片=设计真值，存档=运行时状态。

## 二、讨论结论 → frontmatter 字段快速对应表

| 讨论结论类型 | 写入字段 | 示例 |

| 新称呼（台词出现新称谓） | `aliases`（同步补，供台词匹配兜底） | 慎介：`[慎介, 黑川家的小子, 通译小子]` |
| 关系裁定 | `relations`（wikilink＋关系说明） | `"[[程靖霖]] 孪生兄长（互不知情）"` |
| 出场裁定 | `appearance_scenes` / `first_appearance` | 老孙 D8 深夜牺牲（第七批）→ 场景列表更新 |
| 生死裁定 | `death_status` | 张老大：死亡（D9 遗体） |
| 一句话设定/新结论 | `notes` | 李加夫粗通日语（E-08） |
| 结论来源 | `source` | `裁定表第八批` / `第七批情节问答` |

**禁区（禁止入 frontmatter）**：声望当前值、势力声望变化、关系数值、秘密/里身份的**发现状态**（"玩家已知/未知"）、特殊状态当前等级（发冷1-4 实时值）、任务进度——全部属存档，由运行时系统管理。

## 四、快速落档五步流程（每次问答/会议/审计后）

1. **记真值**：结论写入设计区（裁定表新增批次 / 审计清单标记已裁 / 钩子索引改状态）。
2. **扫受影响卡**：按 §二 字段对应表逐卡落 frontmatter（role/status/faction/secret/aliases/relations/death_status/notes/source）。
3. **事件落 canvas**：事件级结论 → 更新/新建 `Flows/【章】/` 对应 canvas 节点备注。
4. **钩子同步**：H 编号状态随卡更新（留钩子索引为唯一登记处）。
5. **校验**：grep 旧表述清零（如"疫病封禁""D14 承审室"）；确认双链完整、id 未变。

---

## 五、Obsidian 工具链注意

- **narrative-tool 读取** `id/name/role/voice`：改名/改 role 前先查全部 `.ncanvas` 引用与 `Exports/*.dialogue`（id 锁定，改引用再改档案）。
- **narrative-canvas**：Flows 流程图节点可挂备注（讨论结论直接写节点备注，导出 .dialogue 时带出）。
- **双链**：`relations` 用 `[[wikilink]]` 保持图谱连通；卡与卡之间、卡与流程节点之间尽量链接。
- 设计区文档（裁定表/审计/钩子/地图索引）不在 vault 内：需要 Obsidian 内可见时，用 vault 内"速查/索引"笔记做链接指向，或复制关键结论到卡 notes。
