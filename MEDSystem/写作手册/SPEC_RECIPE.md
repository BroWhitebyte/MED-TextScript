# MED Event md → ncanvas spec 配方 v1（与 Event 101-106 同一逻辑）

本文件是「事件 md 转画布」的唯一作业规范。凡与 101-106 已入库的画布冲突，以已入库画布为准。

---

## 〇 真值归属与适用范围（2026-10-01 作者裁定）

> **一切核验以画布 `.ncanvas` 为真值。**

这决定了本配方的**适用范围**：

| 场景 | 本配方是否适用 | 覆盖检查（§五）是否执行 |
|---|---|---|
| **新写件**：有 md、尚无对应画布 | ✅ 适用——按本配方落 spec → 生成画布 | ✅ 必须跑，`缺失 0` |
| **已有画布的件改稿** | ❌ 不适用——**直接改画布**，不要"先改 md 再同步" | ❌ 不执行 |
| **md 与画布已不一致的件**（如 `101`：画布比 md 多 7 个选择点＋1 条死亡支） | ❌ 不适用 | ❌ 不执行 |

**为什么已定稿件不再跑覆盖检查**：`check_coverage.js` 是"md → 画布"的**单向**校验（md 的每个片段是否都在画布里有）。
画布在定稿后叠加的机制（选择菜单、状态机、死亡支）**不在 md 里**，跑覆盖检查不会报错，但会给出"md 是来源"的错误暗示；
若有人据以"以 md 为准回改画布"，会把画布上的机制**整段删掉**。

现行口径全文见 `MEDNarrative\使用说明.md` §〇「真值归属」。

## 一 输入 / 输出

- **输入**：一件 `MED_Demo Event\MED_Demo Event 02XX-…md`（绝对路径由主控给出）
- **输出**：一个 spec JSON，路径由主控给出（`_spec_event{编号}.json`）
- **后续由主控执行**：`_tools\ncanvas_from_spec.ps1`（spec → `.ncanvas`）→ 门户 `.canvas` → 审计

## 二 spec schema（严格，字段名不可改）

```json
{
  "title": "Event 201 固定-领口粮",
  "notes": "转化自 …｜…",
  "entryBody": "Adventure Begins",
  "nodes": [
    { "key": "c01", "type": "Content", "body": "正文（可含 \n 分段，逐字照抄）" },
    { "key": "d01", "type": "Dialog", "turns": [ ["说话人", "台词"], ["说话人", "另一句"] ] },
    { "key": "ch1", "type": "Choice", "choices": ["选项一", "选项二", "选项三"] },
    { "key": "z",   "type": "End",     "body": "" }
  ],
  "edges": [
    { "from": "entry", "to": "c01" },
    { "from": "c01",   "to": "d01" },
    { "from": "ch1",   "to": "c30", "label": "选项一" }
  ]
}
```

硬规则：

1. `nodes` 里**不要**写 Entry（生成器自动加，key 为 `entry`）；`type` 只能是 `Content` / `Dialog` / `Choice` / `End`
2. `key` 唯一，建议：叙述 `c01,c02…`／台词 `d01,d02…`／选择 `ch1,ch2…`／结束 `z`
3. Choice 的 `choices` 是**选项文字数组**；**选择支的连线必须带 `label`，且 label 与某个选项文字逐字相同**（生成器据此写 `choiceIndex`/`choiceOptionId`；label 对不上会直接报错）
4. 每条边 `{from,to}`；非选择支的连线不要写 label
5. **禁写** `requires` / `effects` / `variables`（101-106 全部为空，本批同样为空）
6. JSON 存为 **UTF-8 无 BOM、LF**；用 write 工具直接写，不要用 PowerShell 的 `Set-Content`/`ConvertTo-Json`（会产生 BOM 或 PS 缩进风格）

## 三 节点映射规则（铁律：正文逐字照抄，不得改写／缩写／润色／合并句子）

| md 形态 | 落到画布 |
|---|---|
| 叙述段落 | 一个 `Content` 节点（一段一节拍；过长的段落可按 md 自然段拆，但**不得改字**） |
| 引语（`"…"`/`“…”`/协和语/日语音写） | `Dialog` 节点：`turns` 一条一句，`speaker`＝md 里明确的人名或称呼（账房／保甲差役／伙计／翻译…）；**台词逐字照抄，外层引号保留**（与已入库的 `_spec_event104.json`／`103A` 一致——画布里 turns 带引号） |
| 引语的引出句（如「程时一抬眼看了看他：」） | 单独一个 `Content` 节点，紧接该 Dialog |
| 连续同一说话人 | 可放同一 Dialog 的多条 turns；**说话人一变就换 turn 或换节点** |
| `## 选择` 下每个 `### 选项名（结算：…）` | 一个 Choice 节点的**一个选项**（label＝选项名，去掉括号与结算字样）＋该选项的正文链（照抄） |
| 选项分支的汇合处 | 各分支末边指向 md 中紧随其后的那一段正文节点 |
| 「若昨日去了警署／当铺／大车店」这类**状态分岔** | 同样落 Choice 节点，label 用 md 分支标题原文；并在 notes 里注明「状态分岔（由前日择项决定），非玩家当场选择」 |
| `【教学说明】`/`【看板说明】` 式系统文案 | 保留为 `Content` 卡，正文照抄 |
| `（结算：…）` 带得失含义的 | 落 `【结算】…` `Content` 卡，附在该分支链末 |
| `（进入玩家选择——…：）` 一类纯范式标注 | **不落节点**，写进 notes |
| 跨件占位（「正文见对应任务件（待建）」） | `【编号 名·待建】…` `Content` 卡（104 先例） |
| `〔…〕` 方括号舞台标注 | 落 `【…】` 说明卡（或并入 notes，二者择一并保持一致） |
| `## 白描／## 陈述／## 选择／## 选择必有代价／## 结束转场` | 五环节**范式标题**，不落叙事节拍（结构由连线体现） |
| md 尾部 `> **导演层…**` / `> **状态**` / `> **用途注**` / `> **设定注**` | 不落节点，写进 notes |
| 转场收尾 | 一条 `Content` 卡：`【转场】{下一件编号 名}——{时间·地点}`，再接 `z`（End）。下一件从 md 尾部的「此去向下＝…」或索引取 |

## 四 title 与 notes

- `title`：`Event {3位编号}{A/B} {性质}-{名}` —— 去掉 md 文件名开头的 0 与所有括号后缀。
  例：`MED_Demo Event 0202A-主线-补送-裕昌当铺-（上午-下午-黄昏）（选一项）（无复用）（定稿）.md` → `Event 202A 主线-补送-裕昌当铺`
- `notes` 照 104 写法，用 `｜` 分隔：
  `转化自 {md 文件名}｜{（性质）时间行}｜{地点}｜人物：…｜结构：N 叙述节拍 + M 台词节拍 + 选择点 K 处（选项…）｜md 标记映射：…（哪些标记落为图结构／说明卡／未落节点）｜状态分岔与跨件说明（若有）`

## 五 自检（新写件必做，缺失必须为 0）

> ⚠️ **仅适用于「md 仍是唯一来源」的新写件**（见 §〇）。已有画布的件改稿**不要**跑本步。

```
node "C:\Users\white\Downloads\DS workspace\_tools\check_coverage.js" "<md 绝对路径>" "<spec 绝对路径>"
```

- 输出 `缺失 0` 才算完成；若列出缺失单元，**补节点或补进 notes**，再跑一次
- 不允许用概括／改写来"凑覆盖"；也不允许把大段正文塞进 notes 绕过检查（检查器会单独报告「只在 notes 命中」的数量，超过正文单元 15% 会告警）

## 六 交付报告（回给主控，简短）

1. 输出路径 + 节点统计：`Content x｜Dialog y（turns 合计 z）｜Choice k｜End 1`，边数
2. 每个 Choice：选项 label 列表 + 分支汇合到哪个节点
3. 覆盖检查原文结果（必须 `缺失 0`）
4. 存疑 1–3 条（没有写「无」）：如 md 里的自相矛盾、缺人物名、分支无法闭合等
