## 三、四条背景纪律

1. **背景即角色**——地点、规矩、传言只能通过主角**看见／听见／被告知**出现。禁上帝视角风物描写：
   ❌"县城的夜很冷" → ✅"他呵出的白气在门帘上结了冰"
2. **每天一个风物钩子**——从背景库取一件当天用（冻住的锁、补墙匠的锤声、保甲的簿子、路倒、梆子声），写进上午或黄昏段，**交稿登记防重**。
3. **氛围＞说明**——一句话能演出来，不写三句话解释。
4. **不新增未登记的地点、规矩、人物外号**——新增走与伏笔相同的登记流程。

## 四、冬与夜的状态机

**冬／雪**：雪覆盖痕迹也暴露痕迹（谁夜里经过、谁拖过重物、谁跌倒、谁被抬着走，雪地里有答案）——写证据链时以此为法则。
门轴冻住开门靠踹；纸张发脆墨水发涩；药柜干裂药材脆裂；"如果不是受不了，也不往药房走"（写病人上门的分寸）。

**夜／亮度**：
- 西北最亮（电灯通明，警署值宿房水壶咕嘟）
- 东北只剩火磨坊一股气烧着
- 西南窝棚最活泛（"扒皮抽筋还不算，骨头都能卖出价"）
- **东南只有药房的灯不灭**——主角是"东南夜里唯一的光"（灯灭母题出处，写作时珍惜这盏灯）

## 五、跨媒介对齐（卷宗 → 小说 → 地点卡 → 事件件）

```
研究卷宗（【档】【推】） → 世界设定（序章八章／地点卡）
                        → 小说章节（【虚】，但器物与用语必须真）
                        → 游戏事件件（可解析文本，含结算与条件）
```

**交接规则**：
- 卷宗里的**档案事实**可以在小说里作为背景存在，但**不得在剧情层面解释虚构因果**（史实只做氛围）。
- 小说里确立的称呼、气味、规矩，**事件件必须继承**（如"老头票""协和面""两层墙"）。
- 事件件产生的**新术语**要回填 `MEDSystem/术语表.md`，否则下次写作会打架。

## 八、遇冲突怎么办（2026-09-10 定）

**原则：就地按叙事逻辑决断，不挂"待裁定"上表。**

1. **能就地定的就地定**——同一物两种叫法、两处格位不一致之类，按当时场景的叙事逻辑择一，写完继续。
2. **决断写回一处**——写进 `Hidden_Meaning/{编号} 分支索引.md` 的"设定统一"节，或 `MEDSystem/术语表.md`（涉及名词口径时）。写回是为了**下一次不重复打架**，不是等审批。
3. **同件内不得两种写法并存**——决断的作用域至少覆盖当前事件件。
4. **不得为了绕开冲突而删设定**——冲突允许就地解决，世界不许因此变薄。
5. **真值文件之间的硬冲突**（系统文档 vs 序章正文）：以**序章八章正文**为准（写作手册已定优先级）。

复跑：
```
node scripts/lint_med_events.js        # 文本规范十项
node scripts/analyze_med_events.js     # 结构与一致性
node scripts/stats_personal.js         # 文风红线
```

## 七、改动登记流程（新增设定）

1. 先查是否已存在（`附录A`／术语表／序章八章）。
2. 若确需新增：写清**名称、归属、用途、首次出现位置**。
3. 落到真值文件（序章附录／术语表／地图表），**不要只写在事件件里**。
4. 涉及伏笔的，登记进伏笔表（含回收日）。
5. 跑一次 lint，确认没有引入新的不一致。
