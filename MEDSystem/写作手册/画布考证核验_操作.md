| 轨道 | 回答什么 | 入口 | 产物 | 碰语料库 |

## 二 三条轴线

### 2.1 时点为轴（1942 年 1–2 月）

事件件的时点由登记表给出，不由人凭记忆填：`--period` 显式指定 ＞ `events.json` 该件日期（notes 里的日期优先于目录推断）＞ `rules.json` 默认。

| 天 | 日期 | period |
|---|---|---|
| 序章 | 1942-01-30 黄昏 | `1942-01` |
| D1 | 1942-01-31（康德九年腊月十五·小年） | `1942-01` |
| D2 | 1942-02-01 | `1942-02` |
| D3 | 1942-02-02（处决日） | `1942-02` |

判定逻辑：词表每条带 `timeGuard=from:YYYY-MM`，正文出现该词且 `period` 早于该月时——X 类报 **error**，其余报 **warn**。取词之前先问「这个词在 1942 年 1–2 月的写法是什么」，再问「有没有书证」。

**库内命中之后还要核年代。** 命中页的语境落在 1942 年之外时，只能按 B 类旁证用：

| 陷阱 | 实情 |
|---|---|
| 双鸭山文史资料 第8辑「粮库」 | 密度全库第一，内容全是 1949 年之后（岭东粮库 1949-09 建库、三年困难时期橡子烧酒） |
| 满铁农村调查·惯行类 | 调查的是华北（山东恩县后夏寨、河北滦县宋谢庄），只能作制度类比 |
| 宵禁例证 | 多为 1932 年军事占领期口径，不等于 1942 年县城常态 |
| 出荷督励本部 | 库内两说（1942-10 已在运作 vs 1942-11 才有），工具报 warn 不裁定；安全写法「粮谷搜荷督励本部」 |

**写法纪律**：时点未到或刚到的词写「先兆」不写「既成」——橡子面在 1942-01 宜写「开始出现」，行业「组合」（1942-07 起）在 1 月只能写风声，台词不得出现该词。

### 2.2 历史关键词为锚

关键词是这套流程的检索锚点，来源是画布正文里的名物、制度、称谓、地名、业态。五步固定：

1. **抽词**——以 `【】` 开头的内部卡（`【结算】【转场】【提示】` 等）不进正文统计，不抽；每件取 10–30 个候选。
2. **入册**——对照 `lexicon.tsv`：在册的直接用；不在册的追加行（`id ^ term ^ group ^ aliases ^ disambig ^ kind ^ class ^ timeGuard ^ note ^ extra`）。
3. **归并**——同一物只立主词，其余写法进 `aliases`（用 `|` 分隔）；泛词必须给 `disambig` 消歧词，否则命中上千本会刷屏，`index` 的泛词体检会点名（阈值 300 本）。
4. **检索**——≥3 字的词走 FTS5 trigram（毫秒级）；2 字词只能整表 `LIKE`（约 3–5 秒/词）。
5. **回填**——每跑完一件，把「有实感但没被查到」的词补进词表。首跑命中词偏少通常说明词表没覆盖该件，不代表没问题。

`node $S terms --event <代号>` 先看本件会查哪些词，再决定扩词，比事后补跑省事。

### 2.3 出处到页为证（四级取证阶梯）

本地库优先，联网兜底。每一级在索引里的标记不同，引用强度也不同：

| 级 | 手段 | 标记 | 引用强度 |
|---|---|---|---|
| **L0** | 本地库整页核证（含书页与文章标题） | `✓`（`verified=page`） | 可直接作写作依据 |
| **L1** | 本地库仅片段 | `·`（`verified=snippet`） | 引用前按「著作—页数」回取整页 |
| **L2** | 本地库无书证（缺口／禁用） | C 类 `gapTerm`／X 类闸门 | 保留须加注，或改词 |
| **L3** | 联网检索（`web_search` → `web_fetch`） | `〔网络来源·未入库〕` ＋ URL ＋ 访问日期 | 不得升格为 A 类，不得与 L0 同栏混排 |

**联网兜底的触发与纪律**

- **触发条件**：该词会进正文，而本地库 0 命中，或命中全为异代／异地语境（L2）。
- **顺序**：先 `search` 确认本地结果为空（把「本地查了什么词、命中几本」写进报告，方便复核为什么去联网）→ 再 `web_search` → 命中即 `web_fetch` 取原文，只留搜索摘要不算取到。
- **上限**：同一问题换源 3 次无果即报「查不到」，不得继续换词重试；禁用词表里的 X 类词不去联网找豁免。
- **记录**：联网结论写进索引 §四的「网络兜底」行，给出 URL 与访问日期；**不回填 `citations.seed`**——那份台账只收本地库书证，混入网络来源会让「库内缺口」失真。§五台账另加一行计数（本地 L0／L1 各多少条、网络兜底几词）。
- **禁则**：不得把网络来源写成 `✓`；不得用它替 X 类闸门开豁免；启用本机代理需用户当次明确授权，且不增加换源次数。

## 三 prompt 逻辑

### 3.1 口令 → 动作

| 用户这样说 | 标准动作 |
|---|---|
| 「生成 101 的考据索引」「给 202B 出一份索引」 | `list` 确认在册 → `lint --all` → `index --write` |
| 「生成 101、102、103A 的索引」 | `batch --only 101,102,103A --write` |
| 「对 306 跑体检」「306 这词有没有问题」 | `lint --event 306 --all`（秒级、离线，到这一步为止） |
| 「按 1942-02 给 204 生成索引」 | 同上，附 `--period 1942-02` |
| 「把今天生成的汇总一下」 | `index-events --write` ＋ `history` |
| 「审一下 104」「104 有什么问题」 | 四类体检 ＋ 结构读数 ＋ 产出 `Event104_审查意见.md` |
| 「104 分支是不是太多了」「节点数对不对」 | `audit_flow` ＋ `audit_choice_cost`，按 §四.2 给读数与判据 |
| 「XX 这词 1942 年能用吗」 | `lexicon` 自检 → `terms --event <代号>` 看在册与否 → 补词表行 → `lint` |
| 「本地查不到怎么办」 | 按 §2.3 走 L3：先亮本地命中数，再联网取原文，按 L3 标记记录 |
| 「画布改过了/新加了一件」 | `scan_events.js --write` 重建登记表，再走上面各行 |

### 3.2 自动补齐的默认（口令里不必写）

1. **代号 → 文件＋时点**：查 `events.json`；代号以文件名为准，画布内部旧号存 `alias` 字段（`--event 204A` 同样有效）。
2. **时点**：`--period` ＞ 登记表 ＞ `rules.json.period`。
3. **查什么词**：`lexicon.tsv`；**判据**：`rules.json`。
4. **落盘位置**：`06_MED_TextScript\MED-TextScript\MED_考证索引\<代号>_索引.md`，同时更新 `_事件总索引.md` 与 `.cache\history.jsonl`。
5. **结构读数**：随审查与索引自动带上（索引头部记「N 节点／M 连线」）。

### 3.3 判定顺序（八步）

1. **解析对象**——`--event` 收代号或路径；失败时工具打印可用代号并提示重跑 `scan_events.js`。
2. **登记表新鲜度**——有新增或改名，先 `scan_events.js --write`。
3. **定轴**——确认该件 period，读一眼本时点的闸门词与用词裁定。
4. **读结构**——`audit_flow` 看节点/连线/Entry/End/可达，`audit_choice_cost` 看选择点与支路厚度。
5. **先闸门后检索**——`lint` 排在 `index` 前面：离线、秒级、不依赖检索库。
6. **本地优先**——`index`／`search` 打本地库；本地 0 命中且该词会进正文，才按 §2.3 升到 L3。
7. **两段式写盘**——`index`／`batch` 默认 dry-run，先打印，确认后才 `--write`；画布内容改动一律先给 diff 预览、获准后写盘（这条优先级最高）。
8. **报账**——动手前一行（做什么｜花什么｜多久｜换回什么），收尾一行（跑了几件、本地检索几次、联网几次、耗时、产物清单、返工次数）。

### 3.4 不自动做的事

- 不改画布任何内容；审查报告只提意见。
- 不替作者裁定口径冲突——库内两说并存时报 warn 并写明两种说法。
- 不扩检索范围、不换源重试；配额（`caps`：查询 120／取页 40）超限即停并报账。
- 不用网络来源替时点闸门开豁免，也不把它写成本地书证。
- 用户只问不要求文件时不主动产文件；先答，再问要不要落盘。

## 四 审查轨道

### 4.1 闸门三级与处置

| 级别 | 触发 | 处置 |
|---|---|---|
| **error** | X 类词出现在其存在时间之前（1942-01 写「组合」「通账配给制」） | 必改，或改成先兆写法；`lint` 退出码 1 |
| **warn** | 用词裁定（药房／堂倌／皮手筒／协和面）或口径冲突（出荷督励本部） | 按 note 改写或加注 |
| **info** | C 类缺口词（金镏子／小广场／大氅）／专名重复计数 | 保留可以，首次出现宜加注 |

报告末行 `覆盖：检查 N 词／命中 M 词／未命中的禁用词 …` 用来看**这次体检的广度**：关键禁用词长期「未命中」，说明词表没覆盖到，该扩词而不是庆幸。**未命中不等于可用。**

### 4.2 结构读数：节点、连线、分支

```powershell
$repo = "06_MED_TextScript\MED-TextScript"
node "$repo\tools\audit_flow.js" <画布.ncanvas>        # 节点｜连线｜Entry｜End｜可达｜可终止
node "_tools\check_overlaps.js" <画布.ncanvas>         # 框体重叠
node "_tools\audit_choice_cost.js" <画布.ncanvas>      # 选择点｜每选项独占支｜汇合点｜小结
node "$repo\tools\flow_depth.js" <graph.json>          # 层数（输入为 {root,nodes,links} 图 JSON，排布脚本内部同算法）
```

| 读数 | 出处 | 判据 |
|---|---|---|
| 节点数／连线数 | `audit_flow` 首行 | 与上一版对比增减；连通图下 连线 ≥ 节点 − 1 |
| Entry／End | 同上 | Entry 恰 1 个；主线件 End 通常 1 个，多 End 须能说明意图 |
| 可达／可终止 | 同上 | 两者都应等于节点总数；任一不符即孤岛或死路，属硬问题 |
| 选择点数 | `audit_choice_cost` 首行 | 选择点＝Choice 节点数；教程件应「分步教学＋每步一结算」 |
| 分叉度 | 每处 Choice 的选项数 | 常规 2–4；同名选项属有意设计，不算缺陷 |
| 支路厚度 | 每选项「独占支 N 节点／M 字」 | 独占支 0 节点＝零差别（必看）；<60 字且无结算卡＝支路过薄 |
| 汇合点 | 每处 Choice 末行 | 有共同汇合点为常态；报「多 End」时须能说出各出口去向 |
| 层数／同层节点数 | `flow_depth.js`／排布结果 | 层数＝SCC 缩点后的最长路径；同层节点过多会折成超高柱（106 曾 35 节点同层 → 9483px） |

**「零差别」要分三类读**（2026-10-01 全库实测：79 个选择点／234 个选项）

| 类 | 识别办法 | 实测 | 处置 |
|---|---|---|---|
| **菜单回流** | 选项目标节点有回边指向同一 Choice（hub-and-spoke） | 41 条 | 不算缺陷：菜单项各有回应卡，回到 hub 是设计（如 101 `n55` 六个「看…」→ 各自节点 → 回 `n55`） |
| **同卡合流** | 多个选项指向同一目标节点 | 63 条 | 需确认：同一张卡若不按 flag 分写，玩家读到的后续完全相同（如 103B 三条「送药要紧，快些走吧」→ `n3`；203 四条购物项 → `n48`） |
| **支路过薄** | 独占支 <60 字且无结算卡 | 28 条 | 按 B 级提意见（如 104 四个选项全部过薄，与「自由＝没有后果」同源） |

其余 102 条有实质支。`audit_choice_cost.js` 目前把前两类一并打成「零差别」，读报告时要自己分——工具侧可加回流识别（见 §八）。

**合理性四条**

1. **有分叉必有代价**：每条选项的独占支要么给内容，要么给结算／提示卡；两者都无就是「零差别」，玩家读不到区别。
2. **分支数配得上件型**：教程件（104／105）分步＋每步结算；自由件（203／302）允许多入口，但每个入口都要能收束到同一 End。
3. **节点增量要能说出用途**：改稿后节点数变动，逐条对得上新增内容；连线数不增而节点数增，多半是卡片没接线，回看 `audit_flow` 的孤岛与链尾。
4. **多 End 必须是有意**：106 三 End、306 双 End 是裁定过的设计；新出现的多 End 要在审查意见里说明出口条件。

**版本指纹**：索引头部记「N 节点／M 连线」，审查意见头部记卡型计数。改稿后先比这组数字，再看内容——数字不符说明手上那份索引是旧版本，需要重跑。

### 4.3 文字量与时长（硬性参数）

单件明细：`node "_tools\ncanvas_metrics.js" 101`；全库表：`node "_tools\ncanvas_metrics.js" --all`（加 `--with-unregistered` 连未编号件；`--json` 机读）。每份审查结论与索引都要带这六项：

| 参数 | 口径 |
|---|---|
| **总文字量** | 陈述＋对话＋选择肢，按非空白字符计（含标点） |
| **陈述文字量** | 非 Dialog 节点的 body（Content／End 等）；以 `【】` 开头的内部卡不进正文 |
| **对话文字量** | Dialog 节点的 `turns[].line`；说话人名字属 UI 标签，不计入 |
| **选择肢数量** | `choiceOptions[].label` 计数（缺则退回 `choices[]`），同时给选择点处数 |
| **选择肢长度** | 均长／最短／最长；配合 §4.2 的「独占支字数」判断选项是否过薄 |
| **完成时长估算** | 阅读（基准 300 字/分；快 400／慢 250）＋ 翻页 1.5 秒/屏 ＋ 选择点 4 秒/处 ＋ 选项 1 秒/项 |

速度常数按普通视觉小说的阅读节奏取（含看图与停顿）。要换口径用 `--speed`／`--page`／`--choice` 覆盖，报告里同时写明所用常数。

**两条读数纪律**

1. 内部卡（`【结算】【转场】【提示】【占位】` 等）单独计数、不进正文——它既是占位进度，也是导出端过滤的待办量（全库现 2,612 字）。
2. 时长要标明是**单周目**还是**含全分支**。互斥件（103A／103B、202A／202B）在系列汇总里只计其一，否则整幕时长会被重复计入。

**已核的口径边界**：全库 575 个 Dialog 节点的 `line` 都不内嵌说话人名；仅 4 个非 Dialog 节点含对话行（共 142 字），按陈述计，误差可忽略。

### 4.4 审查意见文档的骨架

`MED_考证索引\Event104_审查意见.md` 是范本，固定七节＋尾注：

| 节 | 内容 |
|---|---|
| 头部块 | 审查对象（路径＋节点/连线＋卡型计数）、**文字量与时长六参数**（§4.3）、审查日期、**方式：只读，未改动该文件任何内容**、已跑哪几项体检、未完成项（语料库不可达时注明「凡涉书证的判断已标待核」）、口径来源 |
| 一 体检结论 | **先说没问题的**：结构闭环与分支读数、文字量与时长读数、时点红线、用词闸门、时代语、人物一致性 |
| 二 必须处理（A 级） | 契约不一致、逻辑互斥，逐条给「现象→影响→建议」，标出最该先修的那条 |
| 三 建议处理（B 级） | 表格：位置｜问题｜建议 |
| 四 时代语与史料（C 级） | 未能核证的词：该去核什么＋核不到时的退路；含 L2 缺口与 L3 网络兜底行 |
| 五 可选优化（D 级） | 机制复用、命名统一、代价标注 |
| 六 建议的处理顺序 | 表格：序号｜事项｜级别｜说明 |
| 七 同源提醒 | 命名分歧、导出端过滤等待办 |
| 尾注 | 「本文只提意见，审查期间未改动 X.ncanvas」；被外部保存过时附复核记（mtime 变化→逐节点比对叙事内容是否逐字一致） |

**分级口径**：A＝必须处理（契约、逻辑）｜B＝建议处理（时序、机制）｜C＝本次未能核证（需查库或联网）｜D＝可选优化。级别与闸门的 error/warn/info 是两套刻度：前者管文本意见的轻重，后者管词表判据的判罚。

### 4.5 审查的硬纪律

1. **只读**：审查报告不改画布，也不顺手改。
2. **未核证就标「待核」**：检索库不可达时，第四节整节降级为「该去核什么」，不得凭印象下判断。
3. **外部保存必复核**：画布 mtime 或体积在审查期间变过，先逐节点比对叙事内容，再声明原结论是否仍有效。
4. **产物命名守纪律**：单件索引一律 `<代号>_索引.md`（纯代号）。历史上出现过 `Event_105_索引.md`／`MED_叶子戏_索引.md`／`105_索引.md` 三份同题索引各自漂移，新增时统一为纯代号，旧名归档。
5. **口径依赖写进报告**：头部写明本次依据 `audit_decisions.md` 与本目录词表，便于日后复核。

## 五 索引轨道

### 5.1 固定五节

| 节 | 内容 |
|---|---|
| ① 闸门结果 | 离线判定，表格：级别｜闸门｜词｜节点｜说明 |
| ② 时点红线 | **穷举**本时点不可用／需注意的词，未命中照样列出，附「本件命中」列 |
| ③ 主题索引 | 按 `rules.json.sections` 分组；表格：词｜词表 id｜对位（证据等级）｜时点｜命中本数｜出处｜原文要点 |
| ④ 泛词体检 | 命中 ≥300 本的词提示补消歧；附 C 类缺口与网络兜底行 |
| ⑤ 检索台账 | 待查词／实际检索／配额｜书目条目｜出处台账｜闸门计数｜覆盖行｜取证强度（L0／L1 各多少条、L3 几词） |

排序固定为「主题分组 → 词表 id → 出处出现顺序」，同输入必得同输出。

### 5.2 出处书写与标记

```
著作 — p{PDF页}（书页 {印刷页}）— 文章标题
```

- **双页码必写**：PDF 顺序页与原书印刷页实测差 10–14 页，只写一个会引错。
- `〔〕` 表章节或卷次名，`《》` 表书名或法规名。
- `✓` 已取整页核对｜`·` 仅检索片段｜`〔未取页〕` 仅命中未核对｜`〔网络来源·未入库〕` ＋ URL（访问日期）。
- 台账里 `verified=snippet` 的条目，定稿引用前按「著作—页数」回取整页。

### 5.3 证据等级

| 级 | 含义 | 用法 |
|---|---|---|
| A | 同代同地直接对应（1942 年 1–2 月、东北／滨江省一带） | 可直接作写作依据 |
| B | 同类实物／制度旁证（异地或略早略晚） | 可写，不得据此作强断言或数字化断言 |
| C | 库中缺口（全库无书证） | 保留须加注或改词；工具报 `gapTerm`（info） |
| X | 闸门词（时点或用语禁用） | 只检查不检索；期限内出现报 error |

网络来源（L3）不进这张表，单独标记。

### 5.4 现行闸门与用词裁定

| 词 | 起始 | 级别 | 依据 |
|---|---|---|---|
| 组合（行业） | 1942-07 | 禁用 | 鹤岗文史资料 第8辑 p88 |
| 通账配给制 | 1943 | 禁用 | 李淑娟 p156；苏崇民 p410（三色通账 1943-07） |
| 出荷督励本部 | 1942-10 | 需注意（两说冲突） | 金名世笔供 1942-10 已在运作 vs 旧口径 1942-11；安全写法「粮谷搜荷督励本部」 |
| 橡子面 | 1941-12 | 需注意 | 太平洋战争爆发后大规模顶替；1942-01 宜写「开始出现」 |
| 出诊／汉医许可 | 1941-01 | 需注意 | 辽宁文史资料 第26辑 p173 |
| 堂倌（用语） | — | 禁用 | 全库仅 1 例且为关内语境；东北口语一律「跑堂」 |

用词裁定：药房 → 药铺／坐堂先生｜堂倌 → 跑堂｜皮手筒 → 皮手闷子｜协和面（无作粮食名的书证）。

**元层豁免**：`rules.json.exempt.metaLayer` 命中时闸门全部跳过（现匹配 106 梦境层；该件同时列入 `noIndex`，batch 默认跳过，总索引标「按裁定不索引」）。

### 5.5 扩词闭环

1. `lexicon.tsv` 追加行（`^` 分隔 10 列）；别名多个用 `|`；消歧词只能单值且不得与主词／别名重复；泛词必须给消歧词。
2. 有本地书证时 `citations.seed` 追加行（`|` 分隔 9 列：`work | pdfPage | bookPage | article | terms | cls | verified | quote | point`）。
3. `node $S build-citations` 编译进 `citations.jsonl`，再 `index --write`。
4. **`kind` 决定查不查**：`calendar` 类（岁时／时辰）只做闸门不检索，`X` 类 + `speech` 同理。会进正文的名物（牌戏、器物、业态）不要标 `calendar`，否则它们在索引里一行不出。2026-10-01 踩过：Event 105 的 `叶子戏`／`斗纸牌` 原标 calendar，教程件索引只剩伙计／看板／掌柜，牌戏本体零行；改 `realia` 后同一次检索从 3 词涨到 11 词，叶子戏一条带回 6 条整页书证。
5. **消歧词要在「开检索」之前试**：同一个词配不同消歧词，命中量差好几倍（实测 `斗纸牌` 全量 6 本／`+戏` 1 本／`+赌` 5 本）。窄到 1 本等于没查，宽到刷屏才需要收。

三个层次汇总：单件看 `<代号>_索引.md` 五节｜跨件看 `_事件总索引.md`（进度、闸门计数、天对照）｜跨次看 `history`（词数、命中、缓存、error 有无累积）。

### 5.6 缓存语义与改稿

- `.cache/terms.json` 是**词级缓存**：键是检索串，跨事件复用，改词表新增词只查新词。
- `.cache/<画布 title>.search.json` 是**单件结果快照**，以逐词完整为准；缓存里缺本次要查的词就补查（曾因只判「缓存非空」漏检 29 个新词）。
- **闸门与节点定位每次重算**：改稿后跑 `index` 不必加 `--refresh`——正文与节点号会按当前版本重新生成，检索结果按词复用。只有复核库内结果或改了消歧词才需要 `--refresh`（或 `--no-term-cache` 关掉词级缓存）。
- 判定索引是否过期，用索引头部的节点／连线数比当前画布。

## 七 边界、坑与未决

**已知边界**

1. 检索库不可达时只有 `lint` 可用——索引整节降级为「待核」，这是设计使然。
2. 引擎不认识网络来源（L3）：联网兜底由执行者手工登记在报告里，不写进 `citations.jsonl`。
3. 台账 `verified=snippet` 的条目仅为检索片段，引用定稿前需回取整页。
4. 出处短名由库内全名截取，个别长副题书名可能截断；需要全名时看 `citations.jsonl`。
5. 「出荷督励本部」库内两说冲突，工具按 warn 报出，不替人裁定。

**环境坑**

1. 不要经 PowerShell 处理中文文本：PS 5.1 读 UTF-8 无 BOM 会按 ANSI 解，`Out-File` 会插 BOM。工具全程 Node 读写 UTF-8 no-BOM／LF。
2. 异体字归一必须单向（`帐→账` 若写成对称交换，正文与检索词互换后互不相等，实测导致禁用词漏报）。
3. 列分隔符：词表用 `^`（别名内部也用 `|`，用 `|` 分列会串列）；`citations.seed` 用 `|`。
4. `node:sqlite` 是实验特性，仅在直连后端使用；日常可走 8080 服务。
5. 改过 Obsidian 里的画布后，重跑 `lint` 前先在 Obsidian 里 Ctrl+R（Reload app without saving），否则读到旧文件；外部写盘也会被 Obsidian 保存覆盖。
6. 别用后台作业启动 8080 检索服务——作业回收会把进程一起带走（2026-09-30 踩过）；常驻请用独立进程或 `_tools\kanglian-ocr\4_启动检索.bat`。
7. 库路径以 `rules.json.lib.db` 为准：2026-10-01 由 `I:` 迁到 `D:\抗联整理_OCR成果`，`I:` 已不存在。迁移脚本 `_handoff\_move_paths.js`。

**未决（等作者裁定，工具不自行收敛）**

1. 时点纪律的单一真相分散在四处；`待裁定-时点纪律收敛.md` 给了三选一（A 以插件为准／B 以仓库文档为准／C 双向互指＋校验和），未执行。
2. `_tools\audit_decisions.md` 与《画布考证规范》是否并进仓库 `MEDSystem\写作手册`，合成《画布检查规范》结构篇／考证篇。
3. `Exports\` 旧编号历史稿清理、导出端 `【】` 内部卡过滤（现状：`【结算】`「（提示：…）」会原样进 `.dialogue`）。
4. 105 的三份同题索引并一份。

### 三 汇总的三个层次

| 层 | 回答什么问题 | 看哪 |
|---|---|---|
| **单件** | 这一件里哪些词有史料、哪些踩时点红线 | `<代号>_索引.md` 五节 |

### 五 词表会越用越宽（这就是复利）

首次跑某天时，命中词可能很少（例如 101 只命中 6 个词）——这**不代表没问题**，而是词表还没覆盖那一件特有的名物。

- 打开 `lexicon.tsv` 追加一行即参与下一轮（`^` 分隔 10 列，文件头有说明）；
- 泛词必须给消歧词，否则命中上千本会刷屏——`index` 的"泛词体检"节会自动提示；
- 有出处时在 `citations.seed` 追加一行，再 `node $S build-citations` 编译进台账。

**建议做法**：每生成一件索引后，把该件里"有实感但没被查到"的词补进词表；几件之后，第二天的件会明显更饱满。
