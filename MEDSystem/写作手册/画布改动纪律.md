# 画布改动纪律（硬约束）

> 立规：2026-10-02　｜　适用：任何 AI 助手、脚本、外部工具
> **本文件优先级高于一切"顺手就好"的便利考虑。**

---

## 一 铁律

> **在取得作者明确确认之前，严禁改动任何画布内容。**

「明确确认」＝作者**书面写明**要改哪个文件、改什么。**不含**以下情形：

- 「你看看 202B 哪里有问题」——那是**要求核对**，不是授权修改
- 「同步一下」——那是**同步**，不是**改稿**
- 「顺手修掉」「既然发现了就改了吧」以外的任何推测性许可
- 助手自己判断"这样更好"

## 二 什么算「画布」

**必须事先确认（每一件单独确认，一次授权不等于长期授权）：**

| 类型 | 路径特征 |
|---|---|
| 事件件 | `MEDNarrative/Flows/**/*.ncanvas` |
| 门户 | `MEDNarrative/Flows/**/*.canvas` |
| 导出稿 | `Exports/*.dialogue` |
| 剧本源 | `MED_Demo Event/*.md` |

**不必事先确认（可自由创建／修改，事后报告即可）：**

| 类型 | 说明 |
|---|---|
| 考证索引 | `MED_考证索引/**`（新建报告、意见书、素材包；**不改画布**） |
| 工具与脚本 | `tools/**`、`_handoff/**` |
| 插件代码 | `.obsidian/plugins/**`（**例外见 §五**） |
| 规范文档 | `MEDSystem/**`、`使用说明.md` |

> **灰区判定**：若一个动作**会改变画布文件里任何一个字节**（正文、台词、选项、连线、坐标、`ui.view`、`notes`），即属"改画布"，**必须事先确认**。

## 三 标准作业程序（任何一次画布改动）

1. **先出 diff 预览**：逐字给出「现状原文 → 建议原文」，指明文件与节点 id；不得只写"优化了措辞"这类概括
2. **说明影响面**：改哪些节点、是否动连线、是否影响其它件、是否触碰 `_tools/audit_decisions.md` 的裁定
3. **落盘前快照**：`node _handoff/_canvas_guard.js check --git` 确认改前状态干净
4. **等作者书面确认**
5. **改动后立即报告**：改前/改后哈希、体积、节点与连线数变化
6. **复查**：`node _handoff/_canvas_guard.js check` 必须显示**只有被授权的那几个文件**发生变化

**未获确认而发现的问题，一律只写进报告，不动手。**

## 四 禁止的"顺手"清单

以下行为**一律视为违规**，即使技术上无害：

- ❌ 排布算法改动后，"顺手把某件重排一下"（排布＝改坐标＝改画布）
- ❌ 修复断链/重复卡时"顺便连上"
- ❌ 统一格式时重写画布 JSON
- ❌ 用脚本批量规范化画布字段
- ❌ 插件自动写入后再"顺手提交"
- ❌ 把画布从测试文件覆盖到正式文件（**覆盖 = 改画布**）

## 五 插件侧的例外与边界

插件代码（`.obsidian/plugins/**`）**可以**修改，但须满足：

1. **不得让插件自动改动画布**——排布、合并、整理尺寸等一切会写盘的功能，**只能由作者点击触发**
2. 改插件后**必须报告**：改了什么、是否需要重载 Obsidian、是否影响已有画布
3. 若插件修复会改变既有画布的排布结果，**不得自动应用**；只报告"重载后点按钮即可生效"

## 六 核验工具

```powershell
# 建/更新基线（画布指纹快照）
node _handoff/_canvas_guard.js snapshot
# 与基线比对 + 与 git HEAD 比对
node _handoff/_canvas_guard.js check --git
```

基线文件：`_handoff/_canvas_baseline.json`（当前 53 个画布的 sha1）。
**任何画布改动都会在 `check` 里显形**——包括坐标级改动。

## 七 违规处置

一旦发现未经确认的画布改动：

1. **立即停止**后续写盘
2. **报告**：改了哪些文件、改了什么、改前哈希
3. **提供回退**：`_handoff/_backup_*` 下的备份，或 `git checkout -- <文件>`
4. 由作者决定保留或回退，**助手不得自行决定保留**
