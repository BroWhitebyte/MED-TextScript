# 意象插件设计（Imagery Hints）

> 记录 `imagery-hints` 插件的需求演化、技术勘察、方案选型与最终决策。
> 目的：让后来的人（包括三个月后的自己）知道**为什么是这样做的**，以及**哪些路走不通、为什么**。
> 版本：v0.4 设计定稿（2026-10-26）｜对应插件 `imagery-hints` v0.4.0｜真机验证通过

---

## 一 缘起

`.ncanvas` 卡片的四种主体（Content／Dialog／Choice／End）原本只有正文。策划在写分镜时，需要在同一张卡里表达**这一屏该怎么演**：

1. 画面意象
2. 声音意象
3. 效果意象
4. 情绪意象
5. 数值意象

前四项是**演出层**，第五项是**系统层**（体力、人情、线索、状态）。

---

## 二 需求演化（三次转向）

| 版本 | 需求 | 形态 |
|---|---|---|
| **v0.1** | 卡片里固定挂五个「意象框」 | 每类一个字符串，常驻显示 |
| **v0.2** | 一段话可能有多重画面／多重情绪 → **每类可重复建立** | 五类全部改为字符串数组，一条一行 |
| **v0.3** | 意象不该是卡片末尾的注脚，要与正文**排成一条时间轴** | 有序块序列，正文块与意象块交替 |

**v0.3 的目标形态**（用户原话的示意）：

```
画面 → 声音 → 正文 → 情绪 → 正文 → 效果 → 正文
```

策划从上往下读，就是这一场的节奏。

## 三 技术勘察（决定方案边界的六个事实）

以下全部从 `.obsidian/plugins/narrative-graph/main.js`（145 KB minified）中实测得出。**没有源码，只有打包文件**——这一个事实限制了后面所有选择。

| # | 事实 | 出处 | 影响 |
|---|---|---|---|
| 1 | **插件已预留 `customFields`**，在 `KNOWN_NODE_FIELDS` 里，但从无读取／渲染／编辑代码 | `KNOWN_NODE_FIELDS = ["id","type","title","body","x","y","choices","choiceOptions","choiceRevealMode","cast","turns","customFields","ports","frameId","width","height"]` | 自定义数据有了**官方认可的家**，不必污染 `body` |
| 2 | **保存是整棵 state 深拷贝**，不按白名单投影 | `serializeSavedState = JSON.stringify(deepClone(state), null, 2)` | 自定义字段能安全往返，不会被剥掉 |
| 3 | **右键完全空闲**（bundle 中搜不到 `contextmenu`，也没用 Obsidian 的 `Menu`） | 全文检索 | 可以独占卡片右键，零冲突 |
| 4 | **节点与选项都带现成 id** | `e.dataset.nodeId = n.id`；`c.dataset.optionId = l.id` | 不必从 `.ng-node-id` 文本反解，不受插件 UI 改名影响 |
| 5 | **保存入口是内部的**：`_afterMutation()` ×15、`scheduleSave()`、`requestSave()`，带防抖 | 全文检索 | 写回必须经视图内部状态，**不能直接改文件**，否则被插件下次保存覆盖 |
| 6 | **引擎的效果词表只有四个动词** `set / add / subtract / toggle`，且 **`requirements` 挂在「连线」上**，节点没有结算字段 | `EFFECT_OPS`、`KNOWN_LINK_FIELDS` | 「数值意象」暂时无处安放 → 先存成自由文本，等系统落位再映射 |

### 由此确立的两条纪律

- **正文真值只能是 `body` / `turns`**。所有现有工具（`audit_flow`、`med_verify`、`.dialogue` 导出、项目脚本）都只读这两个字段。任何"把正文挪到别处"的方案，都会让工具链失明。
- **不做 bundle patch**。插件一升级就失效，且 minified 变量名一改即崩。

## 四 方案选型

### 4.1 三条路线

| 路线 | 做法 | 是否在框体内 | 抗插件升级 | 结论 |
|---|---|---|---|---|
| **伴生插件** | 独立插件，DOM 追加 + 经视图状态写回 | ✅ | ✅ | **采用** |
| 改 bundle | patch `narrative-graph/main.js` | ✅ | ❌ | 否决 |
| 零插件（文本约定） | 在 body 里写 `〔画面〕…` | ✅ | ✅ | 否决（会污染正文，且 `audit_flow` 字数统计失真） |

### 4.2 序列模型的三条路线

| 模型 | 正文存哪 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A 全文双写** | `body` ＋ `sequence` 各存一份 | 序列自包含；块可任意编辑 | **同一句话在文件里出现两次**；文件 +70%；两处可能打架，选错即丢字 | 否决 |
| **B 纯引用** | 只在 `body` | 结构上不可能重复 | 正文被外部改动后引用漂移，且**漂移时无原文可对照** | 改良后采用 |
| **C 序列独占** | 只在 `sequence` | 模型最干净 | 所有现有工具失明 | 否决 |

### 4.3 最终采用：**引用式（B + 冲突时冻结）**

```
正文只在 body 里存一份
序列只存「顺序」与「指向 body 第几段」的引用
每条例引用带指纹，用于检测正文是否被人改过
一旦指纹不符 → 就地把那一段的当前正文抄进序列冻结（只冻结出问题的卡）
```

**为什么这是最优解**

- 文本编辑器、`git diff`、外部脚本、`audit_flow` 看到的都是一份干净的正文
- 文件只增大约 12%（而非 70%）
- 冲突检测不但没有削弱，反而更精确（能说出"第 3 段指纹不符"而不是笼统的"两份不一致"）
- 冻结只在冲突时发生，因此**平时零重复、冲突时不丢字**

## 五 数据模型（v0.3）

### 5.1 节点侧的 `customFields`

```json
"customFields": {
  "sequence": [
    { "t": "visual", "text": "绳圈在晨光里发白" },
    { "t": "sound",  "text": "铜锣声压过背书声" },
    { "t": "para",   "i": 0, "fp": "他绕过广场|一下眼|15" },
    { "t": "mood",   "text": "冷得不敢哭" },
    { "t": "para",   "i": 1, "fp": "保甲在身后喊|让开！|14" },
    { "t": "effect", "text": "镜头随绳圈轻转，停一拍" }
  ],
  "sequenceVersion": 1,
  "seqDigest": "sha1:…"          // 上次由本插件写入 body 后的签名，用于识别"自己写的"
}
```

### 5.2 块类型

| `t` | 含义 | 存什么 | 进正文？ |
|---|---|---|---|
| `visual` / `sound` / `effect` / `mood` | 四类意象 | `text`（全文） | ❌ |
| `para` | 正文段（Content／Choice／End） | `i`（body 第几段）＋ `fp`（指纹） | ✅（就是 body） |
| `turn` | 对话轮（Dialog） | `i`（turns 下标）＋ `fp` | ✅（就是 turns） |

**数值意象不进序列**——它不是"镜头里的一拍"，而是整段结算（用户 2026-10-26 定）。

### 5.3 指纹（fp）

```
fp = 前 8 字 | 后 8 字 | 该段字数
```

例：`"他绕过广场|一下眼|15"`

- 只存**首尾各 8 字**，中间不存 → 不构成重复文本
- 改首、改尾、改长度任一项都会命中 → 漏检率极低
- 空段：`fp = "||0"`

### 5.4 段落切分规则（用户 2026-10-26 确认）

| 节点类型 | 切分 |
|---|---|
| **Content / Choice / End** | 整个 `body` 按**空行**分成段落；若正文无空行则整体算一段 |
| **Dialog** | **一轮一块**，引用 `turns[i]` |

## 六 冲突模型

### 6.1 什么算冲突

```
期望：第 i 段 / 第 i 轮应满足 fp
实际：当前 body 切段后第 i 段的实际 fp

不相等 → 记为「引用漂移」
```

### 6.2 三种冲突来源

| 来源 | 例子 |
|---|---|
| **外部编辑器改正文** | 用插件自带的节点编辑器改了台词 |
| **批量脚本改正文** | 用脚本清理"顿了顿"、统一用词 |
| **Git / 同步合并** | 两台机器各改一处，合并后正文取了另一边 |

**注意：冲突不需要用户做错什么，它自己会出现。**

### 6.3 冻结（用户 2026-10-26 定：**冻结卡，不冻结画布**）

检测到某条引用漂移时，**只在该卡**把这一段正文抄进序列：

```json
{ "t": "para", "i": 2, "fp": "他终于抬了一下眼|眼。|9",
  "frozen": "他终于抬了一下眼。", "conflict": true }
```

- 其余正常的块仍是纯引用，体积几乎不变
- 同文件的其它卡不受影响
- 冲突解决后清掉 `frozen` 与 `conflict`

### 6.4 重对齐（漂移后怎么办）

1. 先按指纹在**当前段落列表**里重新匹配（贪心 + 顺序约束）
2. 匹配上 → 更新 `i` 与 `fp`，冲突消解
3. 匹配不上 → 该意象块标为**未挂接**，沉到卡片底部的「未挂接意象」区
4. **任何情况下都不删内容**

### 6.5 忽略的自动失效（用户 2026-10-26 定）

```
点「忽略」→ 记下当时该段 fp 作为快照
若正文再次变化 → 自动取消忽略并重新报警
```
否则「忽略」会变成一个永久漏洞。

## 七 三道闸（安全联锁）

### 闸 1：检出即锁

**某卡有未解决冲突时，本插件绝不对它的 `body`／`turns` 写回。**

只写 `sequence`，并提示一次「已暂存改动但未写入正文」。
理由：否则会出现——你去改意象 → 插件把过期序列拼回 body → **外部改的正文被悄悄覆盖**。

### 闸 2：覆盖前留底

任何"以序列为准"的覆盖，先把旧正文存进节点：

```json
"_dualWriteBackup": { "body": "被他覆盖掉的原文…", "turns": null, "at": "…", "by": "imagery-hints" }
```
清单里提供「恢复被覆盖的正文」。只留最近一次。

### 闸 3：撤销贯通

所有写入（含覆盖正文）进撤销栈，`Ctrl+Alt+Z` 可退。

## 八 交互设计

### 8.1 卡片内（线性流）

```
┌────────────────────────────────────────┐
│ ◆ 行刑 · 广场                     n2 ● │   ← ● 未处理冲突标记
├────────────────────────────────────────┤
│ 意象 ▾                                 │
│ ┃画面   绳圈在晨光里发白               │
│ ┃声音   铜锣声压过背书声               │
│ ┃正文   他绕过广场，没抬头。           │  ← 引用 body 第 1 段
│ ┃情绪   冷得不敢哭                     │
│ ┃正文   保甲在身后喊：让开，都让开！   │
│ ┃效果   镜头随绳圈轻转，停一拍         │
│ ┃数值   体力 -1 · 人情+ 老韩           │  ← 卡级，不进序列
├────────────────────────────────────────┤
│ ▸ 选项一   ▸ 选项二                    │  ← Choice：选项固定列末尾
└────────────────────────────────────────┘
```

- 块间缝隙悬停出现 `＋`，可插任意类型（含"正文段"）
- 意象块可上下移；**正文块锁定顺序**（用户 2026-10-26 定，防止误触重写正文）
- 双击任意块就地编辑

### 8.2 插入正文段的落位规则（用户 2026-10-26 定）

```
新段插在「前面最近的正文段」之后
若前面没有正文段 → 插在 body 开头
```

### 8.3 状态栏与冲突清单（用户 2026-10-26 定）

- 状态栏（右下角）：`⚠ 双写冲突 2`；无冲突时不显示
- 统计范围：当前活动画布优先，其它文件显示 `⚠ 2（+5 其他文件）`
- 点击 → 清单，**按文件分组、可折叠**
- 每条给出：节点、类型、期望指纹 vs 实际指纹、三个按钮（重建引用／沿用当前正文／忽略）

### 8.4 入口

| 入口 | 位置 |
|---|---|
| 右键卡片 | 新建意象（可重复）／编辑全部意象／收起展开／删除整类 |
| 卡片右上角 `＋` | 同一菜单 |
| 双击块 | 就地编辑 |
| 右键块 | 编辑／下加一条／删除／整类删除 |
| 命令面板 | 意象：为当前节点新建/编辑｜撤销上次删除｜收起展开全部｜只看已忽略的冲突 |

## 九 决策清单（逐条可追溯）

| # | 决策 | 依据 |
|---|---|---|
| 1 | 用伴生插件，不改 bundle | 插件无源码；升级会被覆盖 |
| 2 | 数据存 `customFields` | 插件白名单已预留；保存不剥字段 |
| 3 | 五类意象可重复建立 | 一段话可能有多重画面／情绪 |
| 4 | 序列块与正文形成线性流 | 否则策划理解成本高 |
| 5 | 正文只在 `body`／`turns` 存一份（引用式） | 避免同句出现两次；外部工具只见一份 |
| 6 | 引用带指纹（前8｜后8｜长度） | 漏检率极低，且不重复正文 |
| 7 | 冲突时冻结**该卡**（不是画布） | 减小影响面 |
| 8 | 三道闸全上 | 只有检测没有联锁＝会骗人的提示 |
| 9 | 状态栏 + 分组清单 + 红点标记 | 不打断，但可见可回溯 |
| 10 | 忽略自动失效 | 防止永久漏洞 |
| 11 | 数值不进序列 | 它是结算，不是镜头；且系统未定稿 |
| 12 | 正文块锁定顺序 | 防误触重排＝重写正文 |
| 13 | 切断回退：旧 `imagery` 惰性迁移 | 不一次性重写全库 |
| 14 | 旧数据迁移后意象放卡首 | 与现观感一致，不突然变样 |
| 15 | **Entry 也支持意象**（但**不写正文块**） | Entry 的 `body` 是 `Adventure Begins` 占位，不参与叙事；开场演出仍需画面/效果/情绪 |
| 16 | **Choice 暂不改造** | 选项是结构不是块；增删选项仍走插件自带编辑器，序号级数值已单独支持 |

## 十 风险与已知局限

| 风险 | 说明 | 缓解 |
|---|---|---|
| **DOM 结构依赖** | 注入依赖 `.ng-node`／`.ng-node__body`／`data-node-id`。插件改版可能失效 | 注入前自检；连续 3 次失败弹一次提示，**不影响画布本身** |
| **段落切分漂移** | 用户合并/拆分段落会导致引用错位 | 指纹检测 + 重对齐 + 未挂接区 |
| **`customFields` 形状被他日实现** | 插件将来若真的实现 `customFields`，形状可能不同 | `sequenceVersion` 留版本号；形状写进本文档 |
| **无法验证真机行为** | 打包文件只能读不能跑 | 首次使用需人工验证：重绘后是否仍在、写回是否落盘 |
| **数值意象暂时无系统** | 引擎的 `requirements` 挂在连线上，节点无结算字段 | 先存自由文本，待系统落位做映射层（`free` → `v2`） |

## 十二 附：为什么不用"全文双写"

最初的模型 A（正文在 `body` 与 `sequence` 各存一份）功能上更简单，被否决只因一个具体后果：

> 用文本编辑器打开 `.ncanvas`，同一句话会出现两次；外部脚本、`git diff`、人工审读都会看见两份。
> 更麻烦的是**两份会打架**：用户在插件自带编辑器改了正文，序列还是旧的；此时若按序列回写，**用户的修改会被静默覆盖**。

改成引用式后，这两个问题从**根上**消失：正文只有一份，冲突退化为"位置对不对"而不是"谁对"，最坏结果是位置错乱，**文字永远不会丢**。

### 修复记录：v0.3.1 那个 bug

**现象**：在旧卡上插入一块，原有内容全部消失。

**原因**：旧卡没有 `sequence` 字段，界面显示的是**虚拟序列**（现场算出来的）。插入时调用的 `ensureSeq()` 发现字段缺失，直接造了一个**空数组**当作真序列，于是「原本没落盘的内容」被「空」顶掉。

**修法**：新增 `materializeSeq()`——任何改序列的操作前，先把虚拟序列整份落盘（写时复制）。七个改序列入口全部换用它。

**教训**：**界面上看到的数据，不一定已经存在于文件里。** 凡「显示层派生、存储层缺失」的结构，写操作前必须先固化，否则就是拿空值覆盖。
